RAILWAY - HYBRID LIVE TEST BOT
================================

PROJECT FILES
-------------
live_test_bot.py          Real Telegram Bot / live test engine
source_reader_userbot.py  User-session source reader/importer
requirements.txt          Python dependencies
Procfile                  Default Railway worker for the live bot
Procfile.userbot          Start command for a separate source-reader service
railway.toml              Railway deployment settings
.env.example              Environment-variable template

RECOMMENDED RAILWAY SETUP
-------------------------
Create TWO Railway services from this project:

SERVICE 1 - LIVE BOT
--------------------
Start command:
    python live_test_bot.py

Variables:
    BOT_TOKEN=<BotFather token>

SERVICE 2 - SOURCE READER
-------------------------
Start command:
    python source_reader_userbot.py

Variables:
    API_ID=<Telegram API ID>
    API_HASH=<Telegram API hash>

IMPORTANT
---------
Do not put BOT_TOKEN/API_HASH in the source code or commit a real .env file.
Use Railway Variables.

The source-reader is a Telegram user-session component. Railway only provides hosting;
it does not guarantee that Telegram will allow or keep an account/session active.
Use an account/session that complies with Telegram's rules.

DATABASE / FILE STORAGE
-----------------------
The project currently writes its SQLite database and PDF files to the local filesystem.
For Railway production use, attach a persistent volume if you need question_bank.db
and generated PDFs to survive service redeploys/restarts.

The live bot and source reader are intentionally separate so importing source messages
does not block the live test runner.

NEGATIVE MARKING
----------------
Current project setting: -0.33 for a wrong answer.

REGULAR POLLS
-------------
Telegram quiz polls can carry a correct answer. A normal/regular poll does not contain
a correct-answer field, so it cannot be automatically scored unless a correct answer is
provided separately.
